# ShotGo Agent 开发工作流

[English](DEVELOPMENT.md) | 中文

每项可独立评审的开发均使用新分支。创建分支前，必须切换到指定基线分支，确认工作区可安全切换，并通过 `git pull --ff-only` 从该分支已配置的远程仓库完成快进更新；开发分支只能基于更新后的基线创建。只有用户明确指定时才使用 `release/*` 作为基线。禁止直接在受保护分支开发，也禁止从过期的本地基线开始开发。

分支使用 `feature/<scope>`、`fix/<scope>`、`docs/<scope>` 或 `chore/<scope>`。每个分支只处理一个事项，所有 ShotGo 产品改动必须位于 `AGENTS.md` 规定的产品边界内。

实现前必须把需求行为映射到所有可能受影响的共享模块、契约、调用方、后台任务、数据库路径和兄弟 Agent，并把差异限制在预期所有权边界内。交接前必须针对需求行为执行聚焦检查，并针对每个已识别使用方执行关联回归检查，同时按适用范围执行类型检查、契约测试、lint、翻译与 Agent Note 检查、上游隔离检查以及 `git diff --check`。任何必需检查被跳过、无法执行、不稳定或失败，均禁止交接。

代码发布不设置常驻二次确认门禁。用户当前请求包含合并、推送或部署时，Agent 可以在所有必需检查通过后完成指定序列；仅要求开发、诊断、审查或状态报告时，不得推断已授权生产修改。推送前必须核查远程分支，提升时必须保留完全相同的已测试结果；远程移动或目标异常时应停止，禁止覆盖或自行替换。当前任务授权部署时允许自动部署，但必须记录部署提交或产物、受影响服务、健康检查和回滚结果，禁止重启或部署无关服务。

## 数据库与数据表变更

数据库和数据表修改不要求强制二次确认，也不限制为人工执行。执行前必须重点报告准确的 Migration 或 SQL、受影响 Schema 与数据表、预期行数据或 Schema 变化、依赖服务与代码路径、兼容性风险、验证查询以及备份或回滚步骤。

本地数据库可用时，必须验证 Migration 和数据变更，包括正向迁移、受影响应用行为以及回滚或补偿恢复。必需的本地验证失败或不完整时，禁止生产执行，除非当前任务明确建立了另一条已验证的预发布路径。

只有当前请求授权相关生产变更，且风险报告、备份或回滚路径以及必需验证完整时，Agent 才可以执行生产 DDL、DML、Migration、导入或复制。必须应用最小范围操作，立即验证 Schema 与数据不变量，并检查每个已识别的依赖服务。不得借为 A 功能申请的数据库变更重写无关的 B、C 数据。

## 必需的交接证据

- 开发分支与基线分支；
- 已评审的源提交、集成分支、生产分支和生产远程仓库；
- 执行的准确检查及结果；
- 警告或延期验收项；
- 已识别的受影响使用方及其回归结果；
- 涉及数据库或数据表时，风险报告、本地或预发布验证、执行结果和回滚状态；
- 请求部署时，部署提交或产物、受影响服务、健康检查和回滚状态。
