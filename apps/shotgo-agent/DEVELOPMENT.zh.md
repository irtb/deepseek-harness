# ShotGo Agent 开发工作流

[English](DEVELOPMENT.md) | 中文

每项可独立评审的开发均使用新分支。创建分支前，必须切换到指定基线分支，确认工作区可安全切换，并通过 `git pull --ff-only` 从该分支已配置的远程仓库完成快进更新；开发分支只能基于更新后的基线创建。只有用户明确指定时才使用 `release/*` 作为基线。禁止直接在受保护分支开发，也禁止从过期的本地基线开始开发。

分支使用 `feature/<scope>`、`fix/<scope>`、`docs/<scope>` 或 `chore/<scope>`。每个分支只处理一个事项，所有 ShotGo 产品改动必须位于 `AGENTS.md` 规定的产品边界内。

交接前必须按适用范围执行聚焦类型检查、单元/契约测试、lint、翻译与 Agent Note 检查、上游隔离检查以及 `git diff --check`。任何必需检查被跳过、无法执行、不稳定或失败，均禁止交接。

所有门禁通过后，把已评审的提交保留在开发分支，由用户手动合并。助手不得把开发分支合并到 `master` 或 `release/*`，包括本地合并。推送、创建 Pull Request、部署和删除分支仍是独立操作，必须取得用户明确授权。

## 数据库与数据表变更

修改数据库或数据表必须取得用户第二次明确确认。首先生成准确的 Migration 或 SQL，并列出目标数据库与数据表、预期行数据或 Schema 变化、验证查询、备份或回滚步骤以及应用兼容性影响。展示该预览时不得执行 DDL 或修改性 DML。

ShotGo 所需数据库与数据表必须在本地部署。用户审核或调整拟执行语句，并手动应用到本地数据库；随后助手可以对该本地状态执行只读验证与应用测试。本地验证失败或不完整时，不得交付生产操作方案。

生产数据库操作由用户执行。本地验收通过后，助手只提供已审核的准确语句或从本地复制到生产环境的步骤，以及验证查询；助手不得执行生产 DDL、DML、Migration、导入或复制。只读生产检查也必须位于当前任务已授予的权限内，不得用来绕过数据库修改规则。

## 必需的交接证据

- 开发分支与基线分支；
- 为用户手动合并准备的提交；
- 执行的准确检查及结果；
- 警告或延期验收项；
- 涉及数据库或数据表时，语句预览、本地验证和生产交接状态；
- 确认助手未执行合并或生产数据库修改。
