# Agent Gateway Protocol v1

English | [中文](README.zh.md)

The browser-facing Gateway protocol is frozen at `2026-08-26.2`. [`gateway-v1.openapi.json`](../gateway-v1.openapi.json) defines message submission, structured image/video generation intent, one-shot approval responses, run cancellation, and replayable Server-Sent Events (SSE); [`gateway-v1.ts`](../../src/contracts/gateway-v1.ts) owns the matching runtime types. This protocol is versioned separately from the [Laravel control-plane protocol](../README.md), whose current request version is `2026-08-26.1`.

An optional `generationContext` records the model and options selected in the Canvas UI. Protocol `2026-08-26.2` permits image `parameters.referenceAssets` containing at most nine unique ordered objects whose only field is a positive integer `mediaLibraryItemId`; video contexts, raw URLs, paths, names, bytes, and additional fields are rejected. The Gateway requires the context kind to match the Grant-bound Agent mode, logs the deterministic selection with the user message, and replaces model-supplied quote options with the UI selection while preserving the Agent's final prompt. Laravel resolves media ownership and trusted execution paths and remains authoritative for availability, validation, pricing, charging, and refunds. The model-facing `generation_quote` schema exposes no reference field.

For a rolling release, deploy Agent before Canvas. The Agent returns `2026-08-26.2` to the new Canvas, preserves explicit `2026-08-26.1` scalar requests, and projects `2026-08-25.1` for an undeclared legacy client. Only `2026-08-26.2` accepts image media references. Unknown declared versions fail with `GATEWAY_PROTOCOL_UNSUPPORTED`; previous projections are removed only after their Canvas builds are no longer served or cached. The same Agent sends Laravel request version `2026-08-26.1` but accepts `2026-08-25.1` responses during the API rollout, so deployment order is Agent, API, then Canvas and rollback keeps Agent and API compatibility coupled.

`approval.requested` exposes the Harness-audited pending decision to the owning Canvas Session. The browser answers it through the approval endpoint with `allowed-once` or `rejected`. The Gateway re-authorizes `agent.session.approval.respond`, binds the response to the live authorization context and Session, accepts an identical retry idempotently, and rejects a changed or stale decision. Model text is never treated as approval.

## Session and authorization

Every Session request carries an opaque Capability Grant as a Bearer token. A `GatewaySessionAuthorizer` validates the Grant, requested Session id, and operation-specific capability with Laravel, then returns the authoritative authorization context, Agent mode, and inference route before Harness creates or reads a Session. The stable context binds user, nullable team, space, nullable project, Agent mode, and Session; the in-process service rejects a different context even when the same user knows the Session id. The production Gateway mounts Session routes only with this authorizer and the trusted Agent Presets; health remains available while Session traffic fails closed.

Browser requests originate only from the configured Canvas origin. The Gateway answers its preflight without cookies, permits the authorization, content, idempotency, and replay headers, exposes both protocol-version headers, and rejects any other supplied Origin.

`POST /api/agent/v1/sessions/{sessionId}/messages` accepts one text message and requires `Idempotency-Key` to equal `clientRequestId`. Repeating the same `{sessionId, clientRequestId, message, generationContext}` returns the original `runId` without scheduling another Harness turn; reusing the key with changed content returns `IDEMPOTENCY_CONFLICT`. A Session permits one active run; concurrent submissions return `SESSION_BUSY`.

## SSE replay and cancellation

`GET /api/agent/v1/sessions/{sessionId}/events` streams ordered frames. Each accepted Run and event carries the random `streamEpoch` of the current live Session materialization. The SSE `id` is a monotonic cursor local to that epoch and is not a Harness `sessionSeq`, Laravel project event sequence, canvas revision, or business idempotency key. Canvas resets its cursor when a new accepted Run reports a different epoch. `Last-Event-ID` resumes after the last processed cursor within one epoch. The in-memory replay window retains 512 events; a cursor older than that window fails with `SSE_CURSOR_EXPIRED` instead of silently skipping data.

Each Harness Session event is wrapped as `session.event` and retains its original `sessionSeq`. One of `run.completed`, `run.cancelled`, or `run.failed` terminates the stream for that run. `DELETE /api/agent/v1/sessions/{sessionId}/runs/{runId}` requests cancellation; its `202` response is not the final outcome, because cancellation can race with completion. The terminal SSE frame is authoritative for the Harness run, while Laravel remains authoritative for any business generation already submitted by a Tool.

Session persistence stores the canonical Harness log. A versioned model-invisible binding beside that log records authorization scope, Agent mode, preset, and runtime version without a Grant or credential. After a fresh Laravel authorization exactly matches the binding, the Gateway cold-resumes through `agents.resume()` and opens a new stream epoch. Interrupted inference and approvals are closed, not continued; the next user message starts a new Run. Gateway replay remains process-local delivery state within one epoch.
