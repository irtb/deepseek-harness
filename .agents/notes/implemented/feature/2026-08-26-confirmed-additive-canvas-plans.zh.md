# Agent Note: 经确认的 Canvas 追加计划

Status: implemented

[English](2026-08-26-confirmed-additive-canvas-plans.md) | 中文

## 问题

只读 Canvas 计划预览可以解释工作流，但不能安全地把计划写入画布。若允许模型调用既有通用 Canvas 操作 API，会同时暴露更新和删除能力；若审批界面采用模型填写的数量或积分文本，则可能误导用户确认。

## 决策

Canvas Preset 先读取当前紧凑快照并预览闭合计划，再向 Laravel 请求有效期五分钟的加密计划报价。该报价绑定 Grant 授权上下文、Session、用户、可空团队、空间、项目、Canvas 版本、稳定节点 Key 和稳定连接 Key。报价包含 1 个虚拟 Agent 积分，且绝不调用 Laravel 计费流程。

`canvas_ops_apply` 通过可信单次审批通道消费报价计划。Laravel 锁定项目，验证当前授权和未变化的版本，拒绝已占用 Key 和节点锁，只把新增 `node.upsert` 与 `edge.upsert` 操作交给既有 Canvas 操作服务。既有节点与连接不能被更新或删除。完全匹配的重试不会再次写入或广播；不完整或不匹配的状态安全失败。

## 语言策略

Canvas、Image、Video Agent 的会话推理和回复默认使用简体中文，仅在用户明确要求后切换语言。该默认值绝不限制创作产出的语言，包括作品文案、提示词、脚本、字幕和旁白。

## 考虑过的替代方案

**向模型暴露通用 Canvas 操作 API。** 否决，因为既有操作类型包含本阶段范围外的修改能力，会扩大错误工具调用的影响。

**对 Canvas 计划使用既有 Laravel 积分账本扣费。** 否决，因为本阶段采用临时固定 Agent 数值，不能改变既有生成扣分策略。

**把默认回复语言同时作为产出物语言默认值。** 否决，因为会话展示与用户要求的创作内容是相互独立的意图。

## 后果

用户可以批准一份准确的追加计划，并在对话中看到权威执行结果。报价后发生任何 Canvas 变化都必须重新读取、报价和确认。媒体节点只是占位节点而非生成结果；更新、移动、覆盖、删除和真实 Canvas 操作计费仍不可用。
